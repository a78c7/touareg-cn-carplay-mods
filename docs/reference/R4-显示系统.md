## 1. 屏幕编号

displaymanager 的配置（`displaymanager.json`）里的编号：

| 编号 | 屏 | 接口 | 尺寸 | 范围 |
| --- | --- | --- | --- | --- |
| 0 | 中控屏 | LVDS1 / HDMI1 | 1920×1020 | 【途锐实测】 |
| 4 | 仪表 | LVDS2 / INTERNAL2 | `displaymanager` 上报 1920×722（大众官方标称物理屏为 12 英寸 `1920×720`） | 【途锐实测】 |
| 5 | HUD | MOST | — | 【途锐实测】 |

- QNX 的 `/dev/screen/0` 下能看到两块物理屏（dpy-1 中控、dpy-2 仪表）。【途锐实测】
- CarPlay 主屏协商的分辨率是 1540×720（物理 235×110 mm；注：此为 AirPlay 协议协商的主屏视频流尺寸，区别于 [05 篇](../05-全屏CarPlay与U盘包.md) 中 `skin3/info.txt` 修改的 HMI 视图容器视口 `1152×592 → 1673×748`）。【途锐实测】
- **HUD 不是视频**：车机不给 HUD 发画面，只通过 BAP 发箭头、距离、路名等数据，由 HUD 自己画（见 [R2](R2-HMI-J9-Java.md) 第 7 节）。【途锐实测】

## 2. displayable（窗口）编号

每个要显示到某块屏上的 QNX screen 窗口都有一个编号（窗口的 ID 字符串），displaymanager 按编号决定每块屏显示哪些窗口。

| 编号 | 是什么 | 范围 |
| --- | --- | --- |
| 16 | `DISPLAYABLE_HMI`，中控 J9 原车界面（1920×1020，含左侧快捷栏、顶栏、底部空调栏，中间镂空） | 【途锐实测】 |
| 17 | `DISPLAYABLE_REAR_VIEW_CAM`，倒车影像硬件 Overlay（1083×739 / 360 环影 `zfas` 1920×1020），挂 R 挡强制优先 | 【途锐实测】 |
| 19 | `DISPLAYABLE_MAPVIEWER`，原车中控导航地图窗口（1680×760，归 `navigation` 进程持有；切出后不可抢占，否则退出时原车不会重绑） | 【途锐实测】 |
| 33 | 原车导航的**仪表地图**窗口，1920×639，RGBA8888，GLES2 画。窗口状态显示 INVISIBLE，但内容照样合成到仪表上 | 【途锐实测】。保时捷 PCM 5 上也是 33（来自 fifthBro 的资料） |
| 58 | `DISPLAYABLE_GOOGLE_EARTH_KOMBI_MAP_VIEW`，谷歌地球仪表地图，国内用不到，可以拿来放自己的画面 | 【途锐实测】 |
| 59 | `DISPLAYABLE_EXTERNAL_SMARTPHONE`，中控全屏 CarPlay 主画面（1664×736，由 `dio_manager` 渲染，进入 CarPlay 挂载、切出卸载） | 【途锐实测】 |
| 22、23、60、103、104 | 导航/HUD 其它窗口（其中 60 为 HUD 逻辑窗口） | 【部分已确认】 |

### 中控屏（display 0）实车 5 场景挂载矩阵与触控链路（社区 P2878 只读审计补齐）

- **硬件管线（`graphics.conf`）**：中控 `Display 0 (LVDS1, 1920×1020)` 具备 3 条独立硬件管线：`LVDS1` (p3, order 3)、`capture` (p2, order 2)、`media` (p1, order 1)。
- **5 场景活动窗口（`dmdt gs` 实测，期间仪表 `Display 4` 始终稳定为 `[58, 33]`）**：
  - 全屏 CarPlay：`[16, 59]`（`16` 做外框与底部空调，`59` 填满中央 `1664×736`）；
  - 原车主页 / 原车越野信息 / 挂回 P 挡：`[16]`（`59` 卸载，原车页面画在 `16` 内部）；
  - 挂 R 挡倒车影像：`[16, 17]`（`17` 作为硬件 Overlay 叠加，任何中控扩展实验都必须监听 `17` 并瞬时让位）。
- **中控触控链路**：`graphics.conf` 中 `input = none`（QNX `screen` 不接管中控触摸），真实触摸经 `/usr/bin/rstp`（`/dev/rstp/keypanel`）以 1:1 像素比例（`scaleX=1, scaleY=1`）直接送入 J9 `MIBMain` 分发。

规则（都是【途锐实测】）：

- **同一编号绑定到最后创建的那个窗口。**自己的窗口也叫 33 时，原车的 33 会被挤掉；自己的退出后原车的不会重新绑定，仪表就卡在最后一帧。
- 显示列表里**第一个在最上层**。仪表设成 `[58, 33]`：自己的画面在上面，原车的 33 垫在下面"在场"。只放自己的编号时，仪表会报"加载失败"。
- 仪表的显示列表会被原车切换覆盖：早期版本每 3 秒定期重申；**自 `v21.1` 起改为通过 `DSIProxy` 注册 `DSIDisplayManagementListener` 事件驱动守护**（`[58, 33]` 在位时 0 次多余重申，原车切屏时 ≤100 ms 顶回；不可用固件降级 5 秒兜底）。

## 3. 仪表上谁画什么

仪表画面分两部分：

- **车机发过去的画面**：窗口 33（或你放上去的窗口）。
- **仪表自己画的**：顶部状态栏与导航条（剩余距离、路名、到达时间）、时钟、挡位框、车速框、底部正中小路图标、指针、警告灯、提示框。这些车机改不了，`dmdt ts 4` 也截不到，要定位只能拍照。【途锐实测】

途锐上精确正视标定的位置（以 `1920×639` 仪表窗口画布为准，完整多边形与安全区以唯一坐标真相源 [`CLUSTER_LAYOUT_SPEC.md`](CLUSTER_LAYOUT_SPEC.md) 为准，【途锐特有】）：

| 元素 | 精确位置（`CLUSTER_LAYOUT_SPEC.md`） |
| --- | --- |
| 顶部多层遮挡 | `y = 0..82`（全黑状态栏）+ `y = 82..154`（常态导航顶栏）+ 车道指引扩展至 `y = 190`（全天候安全顶线 `y ≥ 200`） |
| 时钟中心 | `x = 965`（相对画面中心 `960` 偏右 `5 px`） |
| 左下原车挡位斜梯形 | 顶边 `y = 518`，斜边 `x = 314` 扩至底边 `x = 468` |
| 右下原车车速斜梯形 | 顶边 `y = 518`，斜边 `x = 1612` 扩至底边 `x = 1458` |
| 底部正中原车小路图标 | 全天候常驻 `y = 580..639`（`x = 795..1130`）；ACC 开启向上扩至 `y = 495..639` |

拍照定位的方法：在**同一张照片**里找已知坐标的参照（截图里能看到的地图元素），算出比例和偏移再换算。用不同照片估的数互相会对不上。

两侧圆表盘可短按方向盘 `VIEW` 键（或在车机「车辆设置 → 数字驾驶舱」中）隐藏，地图即可全宽铺满。【途锐实测】

### 自己的窗口偶尔不显示

开机后、或者 CarPlay 重连后，早期偶尔出现显示列表是 `[58, 33]` 但画面未切出的现象（系渲染进程画面尚未就绪即提前切屏）；早期 `v19.3` 曾采用连上后 20 秒重启一次显示程序的临时方案，**自 `v19.4` / `v21.1` / `v23.0` 起已改为首帧就绪写 `/tmp/cl_render_ready` 后再切屏 + `DSIDisplayManagementListener` 事件驱动守护**，不再需要 20 秒强制重启闪烁。【途锐实测】

## 4. 画到屏上的方法

| 项 | 结论 | 范围 |
| --- | --- | --- |
| H.264 解码 | NvMedia 硬解可用 | 【途锐实测】 |
| YUV 转 RGB | NvMedia Mixer 在途锐上直接返回错误（不工作），改用 `screen_blit` 做转换；`v23.6` 经 4 槽纯 Pitch-Linear 离屏缓冲 + `glTexSubImage2D` 物理隔离上传 GLES2 纹理（消除 Tegra `USAGE_OPENGL_*` 与 `READ/WRITE/NATIVE` 混用驱动冲突，实车满帧 60 fps） | 【途锐实测】 |
| 半透明叠加 | `screen_blit` 设 `SCREEN_BLIT_TRANSPARENCY = SCREEN_TRANSPARENCY_SOURCE_OVER` 可用 | 【途锐实测】 |
| 中文字与字体 | 早期 `dash.c` 采用编译期预渲染 Noto Sans CJK SC 位图；后续 `navbox.c` 与 `v23` 引擎已直接通过 `stb_truetype.h` 运行时光栅化车机原厂 TTF 字体（`ZYHei_GB18030_c.ttf` + `VWTextCarUI-Bold.ttf`） | 【途锐实测】 |
| 截物理屏 | `screen_read_display`（显示管理权限的 context）能抓中控和仪表的实际输出 | 【途锐实测】 |

## 5. dmdt（车机自带的显示调试工具）

`/eso/bin/apps/dmdt`。【MH2p 通用】

- 要在一个有 `./config -> /etc/eso/production` 的目录里运行，而且要终端（`ssh -tt`），否则没有输出。
- `LD_LIBRARY_PATH=/mnt/app/armle/lib:/mnt/app/armle/usr/lib:/mnt/app/armle/graphics:/eso/lib:/lib:/usr/lib`

| 命令 | 作用 |
| --- | --- |
| `dmdt gd` | 列出所有 displayable |
| `dmdt gs` | 每块屏当前显示哪些 |
| `dmdt sd 4 58 33` | 设置仪表（屏 4）的显示列表 |
| `dmdt ts 4 /tmp/a.png` | 截取车机发给仪表的画面。命令返回后文件还在写，等 2～3 秒再取 |

## 6. 换车型先查什么

1. `dmdt gd` / `dmdt gs`：仪表是哪个屏编号、原车仪表地图是哪个 displayable、有哪些空闲编号。
2. 原车有没有"仪表显示导航地图"的功能。途锐的方案是借用原车地图的位置；原车没有这个位置，就得另找办法。
3. 拍照量出仪表自己画的元素的位置。
