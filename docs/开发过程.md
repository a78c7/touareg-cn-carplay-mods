# 开发过程：CarPlay 导航上 HUD 和仪表（途锐 MH2p 国行 P2878）

这份文档按版本顺序记录了把 CarPlay 导航搬到 HUD 和仪表的完整过程：每一步遇到什么问题、怎么查到原因、怎么解决。目的是让其他车型（同平台的大众、奥迪、保时捷 MH2p 车机）的人能少走弯路。

标注说明：**【途锐特有】** 只在这台车/这个软件版本上验证过，别的车多半要重新找；**【MH2p 通用】** 是平台层面的结论，同平台车大概率一样。

- 车机：MH2p_CN_VWG36_P2878，QNX 6.6.0，NVIDIA Tegra K1（armle-v7），HMI 是 J9 Java（/ifs/lsd.jxe）
- 手机：iPhone（iOS 27）；测试过高德、苹果地图、百度地图
- 工具：MH2p SD ModKit（U 盘刷入）、SSH（[fifthBro/mh2p-ssh-access](https://github.com/fifthBro/mh2p-ssh-access)）、USB 网卡（D-Link DUB-E100，AX88772C）

---

## 第一部分：导航转向信息上 HUD（VW_HUD_1 + VW_HUD_2）

### 1. 原车 CarPlay 为什么不给 HUD 发导航

- 车机的 `dio_manager.json` 里没有声明 iAP2 路线指引消息（0x5200–0x5204），所以 iPhone 根本不发转向数据。**【MH2p 通用】**
- 原厂 CarPlay 只向仪表报一个标志"CarPlay 路线指引激活"，仪表据此显示"导航已在移动设备上激活"，没有任何箭头/距离接口。

### 2. 拿到转向数据：dio_cluster.so

- 用 fifthBro/mh2p-cluster 公开的 `dio_cluster.so`（CC BY-NC-SA 4.0），通过 `smartphone_integrator.json` 里 carplay 进程的 `envs` 加 `LD_PRELOAD` 注入 `dio_manager`，**不修改 dio_manager 本体**。
- 它在 iAP2 Identify 消息里补上 0x5200 系列声明，iPhone 就开始发 RG_Update / RG_Maneuver，写到 `/tmp/cluster_cp.state`。
- 坑：`dio_manager` 同一进程会加载两次钩子，第一次是 root、第二次已降权，第一次建的 0644 文件第二次打不开 → 状态文件一直是空的。解决：开机脚本（Persist）先建好 0666 的空文件。**【MH2p 通用】**

### 3. 把数据送进大众 HMI：Java 插件 VWClusterNav

- 主界面程序 `/ifs/lsd.jxe` 用 luka-dev/jxe2jar 转成普通 jar 后可以反编译阅读，类名没有混淆。
- 往仪表/HUD 发导航的是 BAP NavSD（LSG 50）：`RGStatus`、`ManeuverDescriptor`、`DistanceToNextManeuver` 等，它们都从 ASL datapool 取数据：路线指引状态 = int 732，箭头 = list 751/838，距离 = list 741，路名 = list 744。
- 写一个 OSGi bundle（`src/hud-java`），读 `/tmp/cluster_cp.state`，往这些 datapool 写值，原车 NavSD 自己就会把箭头、距离、路名发给仪表和 HUD。
- 注册方式：jar 放 `/mnt/app/eso/hmi/lsd/jars/`，`bundles.properties` 加 `Bundle.Name.97 / Bundle.Activator.97`，并把 97 加到 `Bundle.Startup.Lateload` **最后**（顺序启动遇到异常会中断后面的 bundle，放第一位会连累语音模块）。
- 大坑：J9 只接受 class 版本 ≤ 48（Java 1.4）。改成 49 会静默加载失败、一行日志都没有。解决：JDK 8 `javac -source 1.4 -target 1.4`，bootclasspath 用 J9 的 `jcl.jar`。**【MH2p 通用】**

## 第二部分：CarPlay 地图上仪表（VW_HUD_3_CarPlayCluster）

### 4. 原车仪表地图是怎么来的

- `displaymanager.json`：display 0 = 中控（LVDS1/HDMI1，1920x1020），display 4 = 仪表（LVDS2/INTERNAL2，1920x722），display 5 = HUD（MOST）。
- 原车导航进程有一个 QNX screen 窗口，id string = **"33"**（1920x639），displaymanager 把它合成到仪表。和保时捷 PCM5 一样。**【MH2p 通用，编号在途锐上验证】**
- 车机自带调试工具 **`/eso/bin/apps/dmdt`**，非常有用（见文末"工具"）。

### 5. 调试环境：SSH + Mac 用的网卡驱动

- 装 [fifthBro/mh2p-ssh-access](https://github.com/fifthBro/mh2p-ssh-access)（用 ModKit 刷入的 SSH 模块，指定 D-Link DUB-E100 网卡），车机地址 172.16.250.248，端口 2012。
- macOS 没有 AX88772C（D-Link DUB-E100）驱动 → 写了一个用户态驱动 `tools/axbridge/axbridge.c`（libusb + utun，自己回 ARP），`sudo ./axbridge` 即可，100M、2ms。
- 坑：**有线 CarPlay 会切断 USB 网卡供电**，调试时请用无线 CarPlay。

### 6. 交叉编译

- 用 clang（`--target=armv7a-none-eabi -mthumb -mfloat-abi=softfp`）+ GNU ld，sysroot 用 luka-dev/qnx65-armv7-toolchain。车机实际是 QNX **6.6**，6.5 的 sysroot 也能用。
- 坑 1：QNX 6.6 的 libc 没有 `__aeabi_memcpy/memclr/ul2d`（clang 会生成）→ 自带 `aeabi_shim.h`。
- 坑 2：lld 链接的 .so 在车机上 `dlsym(RTLD_NEXT)` 返回 NULL（钩子拿不到原函数 → CarPlay 连不上）。改用 GNU ld `--hash-style=both` 解决。
- 坑 3：链接 cl_render 时不能用 `--unresolved-symbols=ignore-all`（screen/EGL 函数会被链成地址 0 → 崩溃），要用同 soname 的桩库让 ld 生成 PLT。
- 车上没有 nohup：后台运行用 `(trap "" HUP; exec 程序 </dev/null >log 2>&1) &`。

### 7. 让 iPhone 发第二路视频（仪表画面，stream 111）

钩子 `cl_probe.so`（`src/cluster-probe`）和 dio_cluster.so 一起 LD_PRELOAD 进 dio_manager，拦截车机自带 libairplay（320.17.1）的导出函数：

- `AirPlayCopyServerInfo`：在 `/info` 里加第二块屏（`displays` 数组里加一个 1920x640、uuid 不同的仪表屏），`extendedFeatures` 加 `altScreen`、`viewAreas`。
- `AirPlayReceiverSessionSetup`：control SETUP 回复里加 `enabledFeatures: [altScreen, viewAreas]`；收到 type 111 的媒体 SETUP 时自己开端口接收。
- 坑：**车机 pf 防火墙**在 carplay0/bcm0 上只放行固定 TCP 端口（5000-5001、5010、6000-6001、6030、6100、6200、7000-7001、7100），随便开的端口收不到连接。用 6200。**【途锐验证，MH2p 大概率相同】**

### 8. 解密：不是 AES，是 ChaCha20-Poly1305

本车 libairplay（HomeKit 配对）屏幕流的加密：**【MH2p 通用（同版本 libairplay）】**

- 配对会话 = `*(session + 0x3E4)`（由 `AirPlayReceiverSessionSetHomeKitSecurityContext` 写入）
- 密钥 = `PairingSessionDeriveKey(pairing, "DataStream-Salt<connectionID十进制>", "DataStream-Output-Encryption-Key", 32)`
- 每个 op=0 包：nonce = 8 字节小端计数器（从 0 开始每帧加 1），AAD = 整个 128 字节包头，正文 = 密文 + 16 字节 tag
- op=1 是明文 avcC（SPS/PPS，NAL 长度 4 字节）。解出来是 H.264 High@3.2，1920x640，约 20fps，关键帧很少。
- 网上的 luka-dev（MHI2Q）代码用的是旧版 AES-CTR，在这台车上不适用。

### 9. 解码显示：fifthBro 的 cluster.c

用 fifthBro 公开的 `cluster.c`（CC BY-NC-SA 4.0）做 H.264 解码+显示（`src/cl_render`），改了几处：

- 花屏：`cb_alloc_picture` 总是选第一个空闲 surface，新帧覆盖参考帧 → 改为轮转分配。
- 闪烁/不出图：NvMedia Mixer 在本车直接返回错误 → 编译 `-DUSE_SCREEN_BLIT`（screen_blit 做 YUV→RGB）。
- 窗口编号可配置（环境变量 `CL_DISPID`），见第 11 步。

### 10. "手机一直不发画面"：权限坑

- 现象：只收到大量 op=1，没有视频帧。
- 原因：调试用的触发文件是 root 建的，钩子在 dio_manager 里已降权为 uid 1037（carplay）删不掉，于是每帧都发一次 forceKeyFrame，手机不停重置编码器。
- 解决：命令文件改为按修改时间触发、从不删除（`/tmp/cl_alt_cmd`）。

### 11. 断开 CarPlay 后仪表卡在最后一帧（最难的一步）

- 一开始我们的窗口也叫 "33"。displaymanager 把 33 绑定到**最后创建**的窗口，原车导航的 33 被挤掉；我们退出后原车窗口不会重新绑定 → 仪表停在最后一帧，只有按 VIEW 才恢复。（fifthBro 的代码注释也提到这个问题，他的做法是断开后放 logo 动画占住 33。）
- 只换成别的编号单独显示：仪表报"加载 CarPlay 失败"。用 dmdt 截图证明车机输出给仪表的画面是正常的，是原车/仪表判断"33 不在显示列表里"。
- **最终方案**：我们用编号 **58**（`DISPLAYABLE_GOOGLE_EARTH_KOMBI_MAP_VIEW`，国内用不到），仪表显示列表设为 `[58, 33]`——**列表第一个在最上层**，原车 33 一直垫在下面"在场"，仪表就不报错；断开时设回 `[33]`，原车地图直接露出来。**【编号途锐验证】**
- 原车按 VIEW 时的流程（反编译 lvdskombi `SwitchToPermanentMapSequenceLVDS` + `ChangeDataRateSequence`）：`showDisplayables(4, [33])` → 地图设可见 → `setUpdateRate(4, 10)`。断开时我们照做一遍。
- 实现：`clusterd` 监控视频流，有流就启动 cl_render 并通过 Java 插件把仪表设为 `[58,33]`，每 3 秒重申一次（防止原车切换把它盖掉）；断流 3 秒后停止并恢复 `[33]`。

### 12. 去掉"导航已在移动设备上激活"

- 来源：BAP NavSD InfoStates（FctID 38）在 CarPlay 路线指引时发 6。只有它调用 `isCarPlayRouteGuidanceActive()`。
- Java 插件用反射把 `APIFactory.carPlayService` 换成一个包装，存在 `/tmp/vwcn_noRG` 时这个函数返回 false。

### 13. 夜间模式

- 车机切换日夜时会调用 `AirPlayReceiverSessionSetNightMode`，它只对主屏生效。钩子同时给仪表屏发一条带 uuid 的 `setNightMode`；连接时按 `/info` 里的 nightMode 初始化。
- 实测：在车机设置里切换日夜，仪表地图同步变深色/浅色。

## 第三部分：v15 改进（车上实时调试）

这一轮用 SSH 连着车机、边开 CarPlay 边改。截图全部用 `dmdt ts 4`（见文末"工具"）自己截仪表画面，只有"仪表自己画的东西"（时钟）截不到，需要拍照做参照。

### 14. 冷启动后要断开重连几次才投上仪表

- 现象：过一晚第一次开车，要断开重连 2～3 次仪表才出 CarPlay 地图；接着用就正常。
- 原因在 Java 插件的 `Rebind` 线程（负责把仪表显示列表设成 `[58,33]`）：
  1. 线程启动时记下 `/tmp/vwcn_rebind` 的修改时间当作"已处理"，然后先睡 40 秒。CarPlay 无线连接往往在开机 30～40 秒就完成，`clusterd` 在插件启动前写好的请求被当成旧请求跳过，地图一直压在原车地图下面。
  2. QNX 文件修改时间精度是 1 秒，断开/重连在同一秒内写两次请求，后一次被漏掉。
- 修复：`clusterd` 每次请求末尾加 `;#<时间>-<计数>`（插件忽略 `#` 开头的段），插件改为比较文件**内容**，5 秒后就开始工作，服务没就绪时下一秒重试。实测：开机第 30 秒 CarPlay 连上，第 31 秒仪表出图。**【MH2p 通用】**

### 15. 车标位置：safeArea / viewAreas

- 仪表地图是手机 App 自己画的，车机能影响的只有"安全区"：`/info` 里仪表屏的 `viewAreas` 数组（每项 = 整个可见区域 + 一个 `safeArea` 子矩形），运行中用 `updateViewArea {uuid, viewAreaIndex}` 切换（iPhone 直接执行，不需要 App 配合，毫秒级生效）。**可见区域必须保持整屏**，只改 safeArea（luka-dev 的结论，本车同样）。
- 实测三个 App 对安全区的理解完全不同（截图测量）：
  - **苹果地图**：车标严格在安全区中心（导航和巡航都是），最好控制。
  - **高德巡航**：车标在安全区中心。**高德导航**：横向在安全区中心，纵向固定在整个画面约 85% 高度、不受安全区影响；并且会往**下一个路口的转弯方向**挪约 210 像素（左转往左、右转往右）。
  - **百度导航**：车标在安全区中心右边约 165 像素；**百度巡航**：完全不理安全区。
- 坑：一开始把 safeArea 设得很低很窄，苹果地图就把车标放到仪表底部的原车信息栏后面看不见了。

### 16. 高屏裁切：让车标更低

- 高德导航时车标纵向只认画面高度，安全区压不下去。办法：`/info` 里告诉手机仪表是 **1920×960**（物理高度按比例放大到 146 mm，保持像素密度不变，地图比例尺不变），`cl_render` 只显示其中一段 640 行（`croptop=230` → 显示第 230～869 行）。手机照常把车放在 960 高画面的约 85% 处，落到仪表上就靠近底部。
- `cl_render` 改动：解码尺寸大于输出高度时，post 窗口按输出尺寸建，`screen_blit` 源矩形取 `(0, croptop, 1920, 639)` 一比一拷贝。640 高的普通流不受影响。
- `croptop` 改了只要重启 `cl_render`（`clusterd` 会自动拉起），不用断开 CarPlay；`tall` 和安全区列表改了要重连（只在 `/info` 里发一次）。

### 17. 对准仪表时钟：用照片定位

- 目标是车标在仪表时钟正下方。时钟、到达时间框、P 挡等是**仪表自己画的**，`dmdt ts 4` 截不到。
- 办法：拍一张导航中的仪表正面照，量出照片里地图左右边缘和时钟中心，按比例换算到 1920 宽画面：时钟在 **x≈965**（不是画面中心 960/985）。第一次用另一张照片估成 985，调了几轮结果互相矛盾，后来在**已知设置**下再拍一张、用车标反推，才得到准确值。教训：参照点一定要用同一张照片里的已知量标定。
- 纵向目标：显示画面第 556 行左右（底部信息栏上方一点）。

### 18. 按 App 自动切换

- App 名来自 iAP2 路线指引的 `SourceName`（TLV 0x13），dio_cluster.so 写进 `/tmp/cluster_cp.state` 的 `source_name`：高德 `高德地图`、苹果 `Apple Maps`（有时 `Apple地图`）、百度 `百度地图`。**只在开始导航时发一次**，重连 CarPlay 后会是空的 → `clusterd` 记住最后一次见到的名字（`/tmp/cl_last_app`）。
- `cl.conf` 规则：`rule=<App 名的一部分>,<1 导航中|0 未导航|*>,<安全区编号>`，从上往下第一条匹配生效；`turn=<App>,<左转用的编号>,<右转用的编号>` 在导航中按下一个动作的方向优先匹配。`clusterd` 每秒读一次状态，变化时写命令文件 `va N`。
- 高德转向补偿：`slot_0_type` 是 iAP2 ManeuverType（1 左转、2 右转、13/14 靠左/靠右、20/21 尽头左/右转、22/23 左/右侧出口……），左转时把安全区中心右移 210、右转左移 210，车标就回到时钟下方（截图验证左右两种都在 965 附近）。
- 导航中"是否在导航"：`session_active && route_state>=1 && route_state!=2 && source_supports_rg!=0`（和 Java 插件的判断一致）。

### 19. 教训：安全区越界会让 iPhone 拒绝整个 CarPlay

- 有一组测试安全区 `y+h=966 > 960`，结果 CarPlay 会话在 `/info` 之后几十毫秒就被拆掉（日志：startSession → TearDown），中控 CarPlay 也连不上，手机连续失败几次后会停一阵不再自动重连。
- 修复：钩子生成 `/info` 时把每个安全区钳在画面内。**【MH2p 通用】**

### 20. 仪表显示剩余距离和到达时间（原车样式）

- 原车导航的调用方式（反编译 `HsmTargetBap.updateDistanceTime`）：`ASLNavBAPAPI.updateBapDistanceToDestination(米, 255, 类型)`（单位 255 = 由 HMI 自动选 km/m）和 `updateBapTimeToDestination2(小时, 分钟, 时间格式)`——后者同时更新"剩余时间"和"到达时间"（到达时间 = 车机当前时间 + 剩余时间）。
- 数据：`distance_remaining`（米，TLV 0x07）、`time_remaining`（秒，TLV 0x06），实测 9500 m / 960 s 和仪表显示的 9.5 km、到达时间一致。
- Java 插件在导航时每 2 秒或数值变化时发送，结束导航发无效值。仪表在 CarPlay 地图上方的半透明条里显示（左：剩余距离，右：到达时间）。
- 同时把当前道路写进 BAP CurrentPositionInfo（ASL 字符串 datapool 738）。但高德不发"当前道路名"（`current_road` 一直为空），苹果地图才有。

### 21. 断开后 HUD/仪表还挂着旧导航信息

- dio_cluster.so 在 CarPlay 断开后不清空 `/tmp/cluster_cp.state`，插件看到的还是"导航中"，旧箭头、距离、到达时间一直挂着；下次连上但不导航时也会把旧路线重新激活。
- 修复：钩子在 CarPlay 会话结束（完整 TearDown）和新会话开始时清空这个文件，插件 3 秒后自动撤下导航显示。实测断开后全部消失。

### 22. 无名道路

- 高德把没名字的路写成"进入 无名道路"，以前为了 HUD 只放短路名把它过滤成空。现在无名/未命名/空路名统一显示"无名道路"（仪表顶部那一行和 HUD 用的是同一个 TurnToInfo 字段）。

### 23. 其它记录

- 中控 CarPlay 上苹果/百度导航时"我的位置"偏右：换回 v14 钩子对比也一样，和改装无关（App 自身的布局）。
- 可复现构建：`lsd.jar` 由 jxe2jar 从车机 `/ifs/lsd.jxe` 转换（约 4 分钟，4.7 万个类），JDK 8 `javac -source 1.4 -target 1.4 -bootclasspath lsd.jar`；`cl_render` 链接用自己生成的同 soname 桩库（`libscreen.so.1` 等只导出用到的函数名），重新编译出的 v14 `cl_render` 与车上运行的版本逐字节一致。

### 已知限制

- 仪表画面内容由手机 App 自己决定。高德的"全览"按钮会把中控和仪表的全览状态对调（高德的问题，网上反馈百度正常）。
- 车机只能让仪表地图按屏幕中心缩放（`changeMapZoomLevel`），不能"回到车位置"。
- 高德转向补偿依赖"下一个动作"的方向，转弯前后高德切视角和补偿的时机可能差一两秒。百度巡航时车标位置不受控制。
- 车机重启后要等导航 App 重新开始导航、发出名字后才会按 App 切换位置。
- 仪表两侧表盘可以在仪表设置里隐藏，地图就铺满了。

## 第四部分：v16 仪表信息框

需求：仪表小窗口里原车的 G 值、功率只有动画没有数字，想在仪表上一眼看到功率、扭矩、G 值等实时数字。没有 OBD 编码工具，所以全部从车机侧做。

### 24. 数据从哪来

- 反编译 `lsd.jar`：DSI 服务 `DSICarVehicleStates` 属性 14 `DynamicVehicleInfoHighFrequent` 带 `currentOutputPower`（kW）、`currentTorque`（Nm）、`longitudinalAcceleration`（m/s²）、`lateralAcceleration`（**g**，原车 SportHmi 代码只把纵向除以 9.81 也印证了）、`engineSpeed`、油门开度、刹车压力、方向盘角、横摆角速度、四轮轮速等；属性 12 是对应的 ViewOptions（state 2 = 可用）。属性 15 中频数据有挡位、变速箱油温。`DSICarKombi`（行车电脑）属性 64 机油温度、63 冷却液、6 瞬时油耗、11 自出发起平均油耗、23 油量百分比。
- 大众车机本来有一个 Sport HMI 模块读功率/增压/G 值，但**国行皮肤（skin3）没有这个页面**，越野页只有指南针/海拔/温度/转向角。原车仪表上的"G 值小窗口动画"是仪表自己画的，车机改不了。
- 只读探针（`vwcn.Perf`，建 `/tmp/perf_on` 开始记录到 `/tmp/perf.log`）实测本车：功率、扭矩、加速度、转速、增压、油门、刹车、方向盘角、横摆、轮速都可用；四轮扭矩分配、四驱扭矩不可用；增压绝对值一直是 0。着车后约 8～10 次/秒。核对：1794 rpm、257 Nm → 48.3 kW，车上报 48.0 kW。**【MH2p 大众通用】**

### 25. 怎么画到仪表上

- 不改大众原生界面：在 `cl_render` 里画。面板在 CPU 上画进一个 RGBA pixmap，每帧视频 `screen_blit` 进 post buffer 之后再 `screen_blit` 一次面板，属性 `SCREEN_BLIT_TRANSPARENCY = SCREEN_TRANSPARENCY_SOURCE_OVER`（本车支持，半透明正常；不支持时代码自动退回不透明）。300 ms 没新视频帧时在最后一帧上补画。
- 中文：车机没有可用的字体库给我们用，干脆在编译时用 Noto Sans CJK SC 把要用的几个标签、数字、单位预渲染成 8 位覆盖度位图（`gen_dash_font.py` → `dash_font.h`），运行时只做 alpha 混合。新二进制没有多出任何动态库导入（`isnan`/`lrint` 会引入 QNX 上的 `_LDclass` 等，自己实现了）。
- 数据：Java 插件 `vwcn.Dash` 只在 CarPlay 地图挂在仪表上时（`Rebind.hold != null`）订阅 DSI，每 200 ms 写一行 `key=value` 到 `/tmp/dash.state`；`cl_render` 每 200 ms 读一次，5 秒没更新就隐藏。

### 26. 坑：车机 /tmp 不能改名

- 第一版 Java 写临时文件再 `renameTo`（避免读到半行），结果框一直不出来：车机 `/tmp` 不支持 rename / link（`ln` 报 Function not implemented），数据全留在 `.new` 里。改为直接覆盖写一整行，读端只用以换行结尾的完整行。**【MH2p 通用】**

### 27. 位置和内容的取舍

- 实拍照片量出：仪表自己的导航条（剩余距离/路名/到达时间）盖住窗口最上面约 160 行，左下角挡位框从约 520 行开始，所以框默认放在 y=172。仪表自己画的元素 `dmdt ts 4` 截不到，只能用照片定位。
- 实际使用后精简到 6 行：功率、扭矩、G 值、转速、机油、变速箱。挡位、油量/续航仪表本身就有；冷却液热车后一直 90°C 没信息量，换成转速（两侧表盘隐藏后看不到转速）。G 值是合成值，正负号取纵向分量（加速 +、刹车 −），只转弯时不带符号——横向的左右用正负号表达不直观。
- 仪表顶部那条导航条是仪表自己画的，透明度改不了。

### 28. 其它

- Rebind 切换仪表显示失败时，v15 每秒重试并写两行日志（日志 300 KB 满了会整个清空）；v16 改为每 2 秒重试、只记一次。
- 换 `cl_render` 不用重启车机：`slay cl_render`，`clusterd` 会立刻用新程序重新拉起；Java 插件改了才要重启车机。

## 第五部分：v17 可自定义 + 改装设置程序（尚未上车实测）

### 29. 信息框可自定义、用大众叫法

- `dash.conf` 的 `items=` 决定显示哪几项、什么顺序（英文 key 或中文名），最多 10 项。框的宽高按所选项计算；字号三档：1～6 项大字（行高 52）、7～8 项中字（40）、9～10 项小字（32），默认位置可用高度 348 像素，三档都不会盖到挡位框。
- 名称按大众说明书：当前消耗、续驶里程、车外温度、机油温度、冷却液温度、燃油存量、制动压力、转向角；"行驶数据"三个存储器**自启动起 / 自上次加油起 / 累计**各有平均消耗、行驶里程、平均车速、行驶时间，框里分两行（上面小字是存储器名）。
- 数据：DSICarKombi 里自启动起 = ShortTerm（属性 11 平均消耗、13 里程/车速/时间），自上次加油起 = Cycle（17、19），累计 = LongTerm（14、16）；三个 General 类结构相同（`CarBCDistance`、`CarBCSpeed`、`CarBCTime` 分钟）。
- 字形仍是预渲染位图（`gen_dash_font.py`），两行标签在生成时排好、裁到墨迹，`dash.c` 按位图高度居中。

### 30. 「改装设置」程序

- 改配置文件、删文件夹对多数人太麻烦，于是在 U 盘根目录放一个小程序（`tools/configurator`，Go 写的，Windows / Mac 通用版）：双击后在本机 127.0.0.1 起一个只有本次有效口令的网页，选功能（安装 / 卸载 / 不处理）、信息框项目和顺序，保存时把不刷的模块移到 `未选模块`（ModKit 只跑 `Mods/*`）、给卸载的模块放 `uninstall.txt`、改写 `dash.conf`（保留注释），并删除 Mac 的 `._*`、`.DS_Store`（车机刷机会被它们卡住）。
- 依赖在程序里强制：装仪表地图必须同时装 HUD（插件版本要配套）；卸载 HUD 必须同时卸载仪表地图。
- 为什么不用纯网页：网页改不了 U 盘上的文件夹（只有 Chrome/Edge 的文件系统接口能做，而且对 U 盘根目录有限制），Safari 用户更做不到；本地程序 + 浏览器界面两个系统都能用，代价是第一次打开有系统安全提示。

### 31. 全屏 CarPlay 改为在车上打补丁

- 以前全屏模块直接带一份改好的 `skin3/viewhandler.zip`（14.6 MB，里面是编译后的大众界面程序），卸载只能靠当初刷机 U 盘里的备份。仓库不应该分发大众的文件，于是改成在车上就地修改。
- 对比原厂和改装版：1246 个条目里只有 `Am.jxe`、`Cm_0409.jxe` 两个变了，大小不变，各差 19 个字节。`src/vhpatch/mkpatch.py` 把差异写成补丁表（条目名、大小、改前/改后 CRC-32、"偏移 原值 新值"），只有这些数字进仓库。
- `vhpatch`（C，zlib 静态编进去，只依赖 libc）：读车上的 zip，按中央目录核对两个条目的大小和 CRC 判断"原厂 / 已改 / 未知"；改的时候解压这两个条目、逐字节核对原值、改完核对新 CRC、重新压缩，其余条目原样拷贝，写完再自检一遍才输出；反向同理。未知版本一律不动。
- 安装时先把车上原文件复制到 U 盘，改好的文件先写在 U 盘上自检，再拷回车机并再检查一次，失败就用备份恢复。U 盘可能是 noexec 挂载，程序先复制到 /tmp 再运行。`info.txt` 只改两个数（注意它是 CRLF 换行，sed 不能用 `$` 锚定）。
- 其余改动本来就能在车上原地还原：`smartphone_integrator.json` 去掉我们的 LD_PRELOAD，`bundles.properties` 去掉 97 号插件，LawPaul 的 FEC 授权在车上有 `granted.fecs.bak`。


## 第六部分：v18 0–100 计时、最大值、行车记录（尚未上车实测）

### 32. 不用车机文件也能编译插件：从 jar 的常量池生成桩类

- 编译 Java 插件原本要从车机导出 `lsd.jxe` 再转换。换个思路：已发布的插件 jar 里，每个调用到的大众类、方法、字段都以完整描述符留在常量池里（`javap -v` 可见），`invokestatic/getstatic` 还说明了是不是静态。`tools/javastubs/mkstubs.py` 据此生成只用于编译的桩类；继承关系字节码里看不出来（向上转型不产生指令），用 `hints.txt` 补三条。
- 验证：用桩类重新编译 v17 源码，14 个 class 与发布的 jar **逐字节一致**。代价是新代码只能用 jar 已经引用过的大众接口，v18 需要的新字段（真实车速、横摆角速度、四轮轮速）改用反射读取，第一次回调时把所有字段名写进 vwcn.log，顺便知道轮速字段叫什么。
- 原生部分同理：QNX screen/EGL/GLES 头文件取自公开的 BlackBerry 10 NDK 目录，桩库按 cl_render 的导入符号生成，重编 v17 的三个程序与发布版逐字节一致。

### 33. 0–100 计时

- 在 Java 的高频回调（8～10 次/秒）里算，不在 cl_render 里算（后者每 200 ms 才读一次数据）。用 `realVehicleSpeed`（真实车速，表显车速一般偏高），没有就退回 `vehicleSpeed`。
- 静止（< 0.5 km/h）后起步开始计时，过 100 km/h 结束，两端都在两次数据之间线性插值。轮速信号在极低速时读 0，起步时刻再用头两个非零点外推回 0 km/h（最多往前 1 秒）。主机上模拟恒定 4 m/s² 加速、数据间隔 90～120 ms 随机：算出 6.944 s，理论值 6.944 s。
- 车速比本次最高点低 3 km/h（松油门/刹车）或超过 30 秒就作废。

### 34. 行车记录

- 插件进程不一定有 U 盘写权限，U 盘也可能是只读挂载。所以分两段：Java 每 10 秒写一个分块 `/tmp/drv_<会话>_<序号>.csv`，HUD_2 的开机循环（root）每 5 秒把写完的分块追加到 `<U 盘>/drive_logs/drive_<会话>.csv` 并删掉。`/tmp/drv_cur` 记录正在写的分块，**在创建分块之前**更新，复制方永远不会拿走还在增长的文件。`/tmp` 是内存，最多积压 60 块（10 分钟），超过就丢数据并记一行日志。
- 开关就是 U 盘里有没有 `drive_logs` 文件夹。刷机 U 盘插着会一直触发刷机，所以「改装设置」加了"U 盘用途"：把 `Data`、`Meta` 改名为 `_Data`、`_Meta`（ModKit 不认），再建 `drive_logs`；改回来就能再刷机。


## 第七部分：v19 左右两个信息框

### 35. 两个框共用一套绘制代码

- `dash.c` 原来是一组全局变量（配置、行列表、字体、尺寸、像素缓冲）。改成两个 `dash_box_t`，`dash_use(i)` 把第 i 个框换进全局变量，原来的布局/绘制函数一行不改。
- `dash.conf` 里 `r_` 开头的键属于右边框（`r_items`、`r_show`、`r_x`、`r_y`、`r_right`、`r_alpha`），其余属于左边框；`tank_l`、`lat_flip`、`alpha` 两个框共用。
- 两个框先各自排版，取较小的字号再统一排一次，保证左右字号一致；再把两个框的高度都设成较高的那个（项目少的框下面留空），左右完全对称。
- `cluster.c` 给每个框一个 pixmap，每 200 ms 各自 `screen_blit`（SOURCE_OVER）到仪表窗口上。
- 位置：左边框右边缘对齐左下角挡位框的斜角（实车照片标定 x≈300），右边框按仪表画面左右对称放在 1620～1915。


## 第八部分：v19.2 第一位车主的反馈（尚未上车实测）

### 36. 开 ACC 时车标被挡住

- 车主反馈：车标太靠下，和自适应巡航（ACC）的标志重叠。ACC 开着时仪表在底部中间画 ACC 标志，正好是车标的位置；调位置时没开 ACC，所以没发现。
- 中频车辆数据里有 `aCCIsActive`（桩类里没有，反射读），插件写进 `/tmp/dash.state` 的 `acc=`。
- `cl_render` 本来就只显示手机 960 行画面里的 640 行（第 16 节的高屏裁切），ACC 开着时把显示的起始行往下挪 `acc_up` 行（默认 80），整张地图连车标一起上移。只改显示哪几行，所以高德、苹果、百度都一样有效，不用重连 CarPlay。每帧最多挪 4 行，看起来是滑上去的。
- 插件每秒至少重写一次状态文件（带递增的 `n=`），`n` 5 秒不变就当作数据过期，地图移回原位。
- 车主的照片显示，底部中间的驾驶辅助图案停车挂 P 挡时也在，是他仪表选的显示内容，不只在开 ACC 时出现。所以又加了一个常驻的"地图上移"（`car_up`），和 ACC 时的上移（`acc_up`）一起放进 `dash.conf`，由「改装设置」调。`cl.conf` 刷机时不覆盖（那是各车自己的校准），`dash.conf` 每次刷机都更新，用户设置放这里才生效。
- 同一张照片里高德的车标偏在中线右边：他的仪表顶部有车道箭头，说明他的高德发了车道信息，很可能开了"车道级导航"。这种模式下高德不按下一个转弯方向挪车标，我们的转向补偿（第 18 节）反而把它推偏。车机拿不到高德的设置（CarPlay 不传 App 设置），能用的间接线索是车道信息：两台车里，发车道信息的高德正是不挪车标的那台。所以 `dash.conf` 的 `amap_turn` 做成三档：2 自动（默认，一次导航中收到过车道信息就不补偿，导航结束重置）、1 一直开、0 一直关；`clusterd` 据此决定用不用 `turn=` 规则。样本只有两个，判断错了可以手动固定。

### 37. 方向盘上下键缩放 CarPlay 仪表地图

- 原车仪表显示导航地图时，方向盘上下键由仪表通过 BAP NavSD **MapScale** 发给车机，车机的处理是 `NavigationService.incrementZoomIndex / decrementZoomIndex`（长按每 500 ms 一步），作用在原车的仪表地图上。
- CarPlay 地图在仪表上时，原车地图（33）还垫在下面，这些请求照样会来。插件用反射把 BAP 的 `NavigationService` 换成一个包装（和第 12 节换 `carPlayService` 的方法一样）：CarPlay 地图在仪表上时，缩放请求不交给原车地图，而是记下来，由一个线程写进钩子的命令文件，钩子发 `changeMapZoomLevel` 给 iPhone；同时"已到最大/最小"一律返回否，免得按键被原车吞掉。其它方法原样转发。
- 第一版上车：缩放能用，但很卡。原因三个：插件两次命令至少隔 1.1 秒；钩子每秒才看一次命令文件、按修改时间（精度 1 秒）判断；钩子每发一步缩放就在接收视频的循环里停 0.3 秒，仪表画面跟着停一下。改成：钩子每 0.1 秒看一次，按内容变化触发（命令末尾带递增序号 `#n`），多步之间只停 60 ms；插件按键后 150 ms 内就写命令。
- 实测百度地图收到缩放请求也不执行（日志里命令都发出去了），只有高德响应。
- 哪个方向是放大，代码里看不出来，默认"增加"= 缩小，车上反了就放 `zoom_flip`。
- 包装类有 75 个方法，用反射从 `lsd.jar` 自动生成委托代码。新代码引用了更多 HMI 成员，所以重新从新 jar 生成桩类，验证用桩类重新编译出来的 19 个 class 和用 `lsd.jar` 编译的逐字节一致。

### 38. 百度的路名

- 以前只去掉开头的"进入、驶入、沿、经"等词。百度的句子是"左转进入XX路""向右前方行驶进入XX"，词不在开头。改成在整句里找"进入、驶入、前往、沿着、经由"，取最后一个后面的部分，再去掉结尾的"方向、行驶、直行"。
- 顺便修了一个反向的错误：单字"沿""经"也被当成前缀，"沿江大道""经三路"会被截掉第一个字。现在只有"沿XX行驶 / 直行"这种完整句式才去掉"沿"。

### 39. 其它

- 最大功率 / 最大扭矩：取至少持续 0.3 秒的最高值（0.3 秒窗口里的最低值），深踩瞬间的单点冲高不再算数。
- 当前消耗：停车时偶尔报 32770，按无效值过滤。

## 工具

- **dmdt**（车机自带 displaymanager 调试工具）：需要在一个有 `./config -> /etc/eso/production` 的目录里运行，并且要终端（`ssh -tt`），否则输出会丢。
  - `dmdt gd` 列出所有 displayable；`dmdt gs` 每块屏当前显示哪些
  - `dmdt sd 4 58 33` 设置仪表显示列表
  - `dmdt ts 4 /tmp/a.png` 截取仪表画面（需要 `LD_LIBRARY_PATH=/mnt/app/armle/lib:/mnt/app/armle/usr/lib:/mnt/app/armle/graphics:/eso/lib:/lib:/usr/lib`；命令返回后文件还在写，等 2～3 秒再取，否则 PNG 不完整）。截到的是车机发给仪表的画面，不含仪表自己画的时钟、指针、提示框。
- `cl.sh`（装在 `/mnt/app/eso/bin/apps/cluster/`）：`cl.sh va N` 实时切安全区、`cl.sh ui N` 切仪表场景、`cl.sh tall 960 230` 下次连接用高屏、`cl.sh` 看状态（`/tmp/cl_status` 一行汇总：会话、111 流、帧数、当前安全区）。
- 远程重启车机：`echo gem-reset > /dev/ooc/system`（ModKit 用的方法）；只重启 CarPlay 进程：`slay dio_manager`（会自动拉起，iPhone 自动重连）。
- 车机 shell 的坑：`/tmp` 不能建子目录；没有 `sed`、`strings`、`which`、`uptime`；`grep` 不支持 `\|`；`/mnt/app` 开机是只读，写之前 `mount -uw /mnt/app`。
- `tools/screen/scrcap.c`：用 screen_read_display 抓物理屏
- `tools/axbridge/axbridge.c`：macOS 用的 AX88772C 用户态驱动
- 日志：`/tmp/cl_probe.log`（钩子）、`/tmp/clusterd.log`、`/tmp/vwcn.log`（Java 插件）、`/tmp/dio_cluster.log`。U 盘根目录建 `cluster_logs` 文件夹插在车上，日志会自动拷进去。

## 给其他车型的建议

1. 先装 SSH，用 `dmdt gd/gs` 看仪表是哪个 display、原车地图是哪个编号、有哪些空闲编号。
2. 用 `pfctl -sr` 看车机 pf 防火墙规则，接收端口要用放行的。
3. 看 libairplay 版本和导出符号，确认加密方式（第 8 步）。
4. 反编译 lsd.jxe 找仪表地图的显示流程（搜 `showDisplayables`、`switchContext`）。
