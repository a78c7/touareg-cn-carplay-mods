# 04 仪表信息框

[← 目录](README.md)

需求：原车仪表小窗口里的 G 值、功率只有动画没有数字，想在仪表上一眼看到功率、扭矩、G 值等实时数字。没有 OBD 编码工具，所以全部从车机侧做：在 CarPlay 仪表地图左侧叠一个半透明小框。

## 1. 数据从哪来

反编译 `lsd.jar`（方法见 [01 篇](01-调试环境与工具.md)）找到车机本来就能收到的 DSI 数据：

- `DSICarVehicleStates`
  - 属性 14 `DynamicVehicleInfoHighFrequent`：`currentOutputPower`（kW）、`currentTorque`（Nm）、`longitudinalAcceleration`（m/s²）、`lateralAcceleration`（**g**，原车 SportHmi 代码只把纵向除以 9.81 也印证了）、`engineSpeed`、`acceleratorPosition`（%）、`brakePressure`（≈ bar）、`wheelAngle`（方向盘角度 °）、`yawRate`（°/s）、四轮轮速、车速等。
  - 属性 12：上面各项的 ViewOptions（state 0 = 没有，1 = 装了但无效，2 = 可用）。
  - 属性 15（中频）：挡位、变速箱油温、kickdown、是否在刹车、ACC 等。
  - 属性 17（SemiStatic）：最大功率、最大扭矩、最大增压。
- `DSICarKombi`（行车电脑）：属性 64 机油温度、63 发动机冷却液温度、6 当前消耗、23 油量百分比；"行驶数据"三个存储器（按 2018.07 原厂说明书官称）——`自启动起` = ShortTerm（属性 11 平均消耗、13 里程/车速/时间），`自上次加油后` = Cycle（17、19），`累计` = LongTerm（14、16）；三个 General 类结构相同（`CarBCDistance`、`CarBCSpeed`、`CarBCTime` 分钟）。
- 自 `v21.0` 起另只读接入 `DSICarComfort`（RDK 直接胎压监测，bar）、`DSICarDrivingCharacteristics`（车身俯仰/侧倾角，需配备空气悬架；无空悬如中规 2021–2022 eHybrid 无上报）与 `DSINavigation`（GNSS 海拔），合计 43 项遥测（见 [R3](reference/R3-车辆数据接口.md)）。

背景：大众车机本来有一个 Sport HMI 模块读功率/增压/G 值，但**国行皮肤（skin3）没有这个页面**，越野页仅显示罗盘/转向角/机油与发动机冷却液温度（部分装备/固件版本含海拔）。原车仪表上的 G 值小窗口动画是仪表自己画的，车机改不了。

## 2. 先做只读探针，实测本车

- 探针（Java，开关文件控制，只订阅不写）把回调记到日志。本车结果：功率、扭矩、加速度、转速、油门、刹车、方向盘角、横摆、轮速、车速都可用；四轮扭矩分配、四驱扭矩不可用；增压绝对值一直是 0（虽然标为可用）。**【MH2p 大众通用，具体可用项按车型】**
- 频率：着车后 8～10 次/秒，熄火约 3 次/秒。显示数字够用，做 G 值小球就得插值。
- 核对：1794 rpm、257 Nm → 算出 48.3 kW，车上报 48.0 kW，自洽。怠速 660 rpm 约 1.8 kW / 25 Nm。
- 单位：起步纵向 +3.2、刹车 −5.12（步长 0.16）是 m/s²；低速打满方向横向 ≈ −0.16，和横摆角速度 × 车速推算一致，是 g。
- 当前消耗的单位码会随行驶在 L/100km 和 L/h（停车时）之间切换。
- 油箱只给百分比，升数 = 百分比 × 油箱容积（中规燃油 2.0T/3.0T 为 90 L，中规 2021–2022 eHybrid 为 76 L，欧规标配 75 L，可配置）。

## 3. 怎么画到仪表上

- 不改大众原生界面：在 `cl_render` 里画。面板在 CPU 上画进一个 RGBA pixmap，每帧视频 `screen_blit` 进 post buffer 之后再 `screen_blit` 一次面板，属性 `SCREEN_BLIT_TRANSPARENCY = SCREEN_TRANSPARENCY_SOURCE_OVER`（本车支持，半透明正常；不支持时代码自动退回不透明）。300 ms 没新视频帧时在最后一帧上补画。
- 中文与字体：早期 `v17` 的 `dash.c` 为零新增动态库导入，编译时用 Noto Sans CJK SC 把固定标签、数字、单位预渲染成 8 位覆盖度位图并在运行时做 alpha 混合；后续 `navbox.c` 与 `v23` 引擎已定位并直接通过 `stb_truetype.h` 运行时光栅化车机自带原厂 TTF 字体（`ZYHei_GB18030_c.ttf` + `VWTextCarUI-Bold.ttf`），可显示任意中文路名与自定义皮肤文本。
- 数据通道：Java 插件只在 CarPlay 地图挂在仪表上时订阅 DSI；早期 `v17–v21` 每 200 ms（5 Hz）写一行 `key=value` 到 `/tmp/dash.state`，**自 `v22.0` 起已提频至每 100 ms（10 Hz）并配合 `smooth=1` 指数阻尼插值**（见第 13 节）；`cl_render` 5 秒没更新就隐藏。
- G 值：合成值 `sqrt((纵向/9.81)² + 横向²)`，0.5 指数平滑（滞后约 0.2～0.3 秒）；正负号取纵向分量（加速 +、刹车 −），只转弯时不带符号——横向的左右用正负号表达不直观。

## 4. 坑：车机 /tmp 不能改名

- 第一版 Java 写临时文件再 `renameTo`（避免读到半行），结果框一直不出来：车机 `/tmp` 不支持 rename / link，数据全留在 `.new` 里。改为直接覆盖写一整行，读端只用以换行结尾的完整行。**【MH2p 通用】**

## 5. 位置和内容的取舍

- 实拍照片量出：仪表顶部双层原车遮挡（`y=0..82` 全黑栏 + `y=82..154` 导航顶栏，早期粗估约 160 行）和左下角挡位斜梯形（精确顶边 `y=518`、斜边从 `x=314` 扩至底边 `x=468`，早期粗估约 510～520 行），所以框最初放在 y=172，后续按精确标定对齐 `y=164..508`（详见第 11 节及唯一坐标真相源 [`docs/reference/CLUSTER_LAYOUT_SPEC.md`](reference/CLUSTER_LAYOUT_SPEC.md)）。**【途锐特有】**
- 默认 6 行：功率、扭矩、G 值、转速、机油温度、变速箱油温。挡位、油量/续航仪表本身就有；冷却液热车后一直 90°C 没信息量，换成转速（两侧表盘隐藏后看不到转速）。
- 仪表顶部那条导航条是仪表自己画的，透明度改不了。

## 6. 可自定义（v17 / v21+ 演进）

- 配置文件 `dash.conf` 的 `items=` 决定显示哪几项、什么顺序，最多 10 项。早期 `v17` 字号分三档（1～6 项行高 52、7～8 项 40、9～10 项 32）；**自 `v21.0` 起已重构为大字粗体 + 运动刻度条排版**（1～5 项锁定 `46px Bold` 数字 + `24px Bold` 项目名，6 项 `41px Bold`，左右两框字号独立计算；`v23.0` 升级为四色热力渐变运动条）。
- 名称按大众说明书：当前消耗、续驶里程、车外温度、机油温度、发动机冷却液温度、燃油存量、制动压力、转向角，以及三个存储器（`自启动起` / `自上次加油后` / `累计`）各自的平均消耗、行驶里程、平均车速、行驶时间。
- 行车电脑三个存储器的读数已上车核对，和原车"行驶数据"页一致。

## 7. 0–100 计时

- 在 Java 的高频回调（8～10 次/秒）里算，不放在 `cl_render` 里（`cl_render` 只按写盘节拍轮询状态文件，早期为 200 ms、v22 起为 100 ms，精度不如高频回调）。
- 用 `realVehicleSpeed`（真实车速，结构同 `CarBCSpeed`，桩类里没有，靠反射读），不用表显车速：表显车速一般比真实高几个百分点。**【MH2p 大众通用，字段名以反射日志为准】**
- 状态机：车速 < 0.5 km/h 时"上膛"；越过 0.5 km/h 开始，越过 100 km/h 结束，两个时刻都在前后两个采样之间线性插值，所以精度不受 0.1 秒的采样间隔限制。中途车速比本次最高点低 3 km/h（松油门/刹车）或超过 30 秒就作废。
- 坑：轮速信号在极低速时一直读 0，起步后第一个非零采样已经是好几 km/h，直接取 0.5 km/h 的插值点会把起步算晚。解决：拿起步后前两个非零采样**外推回 0 km/h** 当起点，并限制在"最后一个读 0 的采样往前 1 秒"到"第一个非零采样"之间。用模拟数据测，修正前偏差约 0.09 秒，修正后和真值一致。
- 显示：起步后实时显示已用秒数，过 100 显示成绩并保留到下一次。

## 8. 最大值和扭矩的口径（实测）

- "最大功率 / 最大扭矩 / 最大 G 值"从车机开机算起，熄火关机就清零。加了合理范围（功率 < 600 kW、扭矩 < 1500 Nm、G < 2.5），防止一个坏采样一直挂在最大值上。
- 发动机上**没有扭矩传感器**，`currentTorque` 是发动机 ECU 用进气量、点火角、喷油量等估算的，经网关转给车机。车机报的功率就是 ECU 用同一个扭矩算的：行车记录里每一行都满足 **功率 = 扭矩 × 转速 ÷ 9549**（误差 1 kW 以内）。
- 途锐 3.0T 实测：油门 68% 加速时，2700～3800 rpm 扭矩稳定在 450～460 Nm、持续约 3 秒，比额定 450 Nm 略高。车自己在 SemiStatic 数据里报的最大扭矩也是 450。**【途锐特有】**
- 口径：厂家公布的功率扭矩按国标（GB/T 17692）在发动机台架上测，是曲轴端，没扣变速箱损失；车机报的扭矩和它同一端，可以直接比。底盘测功机测的是轮上，低 15%～20% 很正常。略高于额定的原因可能是估算误差、短时超增压或"内部扭矩"口径（没扣摩擦损失），接口里没写，要靠大油门记录判断。

## 9. 行车记录到 U 盘

- 想把高频数据全部记下来分析，但插件进程不一定有 U 盘写权限，U 盘也可能是只读挂载。所以分两段：
  1. Java 把每个高频回调记一行 CSV，每 10 秒写一个分块 `/tmp/drv_<会话>_<序号>.csv`。**先**把"正在写哪个分块"写进 `/tmp/drv_cur`，再创建分块，搬运方就不会拿走还在写的文件。
  2. 开机脚本（ModKit 的 Persist，root）每 5 秒把写完的分块 `mount -uw` 后追加到 U 盘 `drive_logs/drive_<会话>.csv`，成功再删 `/tmp` 里的分块。
- 开关就是 U 盘根目录有没有 `drive_logs` 文件夹（脚本建一个 `/tmp/vwcn_log_on` 告诉 Java）。U 盘上不能有 `Data`、`Meta`，否则一插就进入 ModKit 刷机。
- `/tmp` 是内存：最多积压 60 个分块，再多就丢数据并记一次日志。熄火时最后不到 10 秒可能没存上。
- 时钟从 1970 开始（见 01 篇第 8 节），会话名会重复：每次开机第一个分块挑一个 U 盘上还没有的文件名，记在 `/tmp/drv_map_<会话>` 里，同一次开机后面的分块都追加到它。
- 约 10 行/秒，每小时约 5 MB（`v21.0` 起已扩充至 34 列真实物理传感器数据）。原厂 DSI `currentGear` 行驶中常报 0/1；**自 `v21.0` 起已在 `Dash.java` 中加入基于 2023 款 3.0TSI 实车采埃孚 8AT 锁止齿比的兜底推算，输出 `D1～D8 / S1～S8` 挡位**（注：2.0TSI 或 eHybrid 纯电/混动模式下可能存在齿比或解耦偏差）。

## 10. 左右两个框

- 原来的绘制代码是一组全局变量（配置、项目列表、字体、尺寸、像素缓冲）。改成两个框结构体，`dash_use(i)` 把第 i 个框换进全局变量，原来的排版和绘制函数一行不改。
- 配置里 `r_` 开头的键属于右边框（`r_items`、`r_show`、`r_x`、`r_y`、`r_right`），油箱容积、横向 G 方向、透明度两个框共用。
- 早期 `v19` 两个框共用较小字号统一重排；**自 `v19.2` / `v21.0` 起改为左右两侧字号完全独立计算**，仅共享等宽等高对齐（左右黄金栏 `295×344`，互不拖累缩小）。
- `cl_render` 给每个框一个 pixmap，每帧各自 `screen_blit`（SOURCE_OVER）到仪表画面上。

## 11. 用照片对齐位置

- `dmdt ts 4` 截不到仪表自己画的导航条、挡位框、车速框（01 篇第 4 节），只能拍照：在照片上找已知坐标的参照（截图里能看到的地图元素和照片对上），算出比例和偏移。早期粗估导航条底边约 `y=156`、挡位框顶边约 `y=509`、斜角约 `x=300`；**最新 `v23.0` 正视逐像素标定精确坐标已统一收口至唯一坐标真相源 [`docs/reference/CLUSTER_LAYOUT_SPEC.md`](reference/CLUSTER_LAYOUT_SPEC.md)**：顶栏双层遮挡 `y=0..82`（全黑）+ `y=82..154`（导航顶栏，安全顶线 `y>=164`）、左下挡位斜梯形 `(0,518)→(314,518)→(468,639)→(0,639)`、右下车速斜梯形 `(1612,518)→(1920,518)→(1920,639)→(1458,639)`、以及全天候常驻的底部正中小路禁区 `(890,580)→(1035,580)→(1130,639)→(795,639)`。**【途锐特有】**
- 改成"给定右边缘"：配置 `right=` 指定框的右边缘，宽度固定后先收紧左右留白和列间距，还放不下再换小一号字体。途锐最终采用左右严格镜像对称的黄金标准栏：左 `x=5..300, y=164..508`（`295×344`）、右 `x=1620..1915, y=164..508`（`295×344`），与下方 `y=518` 挡位/车速梯形及上方 `y=154` 顶栏均留 `10 px` 呼吸缝。

## 12. 其它

- 换 `cl_render` 不用重启车机：`slay cl_render`，`clusterd` 会立刻用新程序重新拉起；Java 插件改了才要重启车机。
- 插件切仪表显示失败时重试间隔不要太短、日志只记一次，否则日志很快写满被清空。
- **可选行车记录 U 盘的介质提示**：绝大多数车主并不需要长期插 U 盘录 CSV；若启用该进阶功能，务必使用品牌正品 U 盘（如闪迪/三星/铠侠），避免车辆突然断电导致杂牌 U 盘 FAT32 分区损坏。

## 13. v22.0 / v23.0 升级：10Hz 阻尼平滑与 60fps OpenGL ES 2.0 + QuickJS 引擎

早期版本中 `Dash.java` 每 200 ms（5 Hz）写一次 `/tmp/dash.state`，数值展示已够用，但画转速/扭矩/G 值运动条会出现肉眼可见的阶跃跳格；另外若社区开发者尝试用 CPU 软渲染在 `1920×639` 画布上做全屏动画，很容易受限于 Tegra K1 CPU 带宽而掉帧。

`v22.0` 与 `v23.0` 保持原有稳态 `capture=h264` 地图管线与窗口 `58`（`[58, 33]`）覆盖机制不变，做了以下核心升级：

1. **10Hz 遥测 + 指数阻尼插值（`smooth=1`）+ 四色热力渐变（`v23.0`）**：`Dash.java` 输出间隔缩短至 100 ms（10 Hz）；`dash.c` 新增 `smooth=1`（默认开启），对转速、功率、扭矩、油门、制动、G 值、转向角等动态运动条做指数阻尼补间，且在插值收敛期间将重绘节拍临时提升至 33 ms（~30fps），稳态巡航时自动回落至 300 ms，不增加常态 CPU 负载。
2. **统一单画布 60fps OpenGL ES 2.0 + QuickJS 引擎（`v23.0` 正式版，`src/cl_render/v23_gles.c`）与独立纯 C 通道（`v22.0`，`src/cl_render/gles60.c`）**：
   - **`v23.0`（`v23_mode`，推荐）**：同一窗口 `58` 内通过 `EGL_KHR_image_pixmap` 硬件零拷贝将实时 CarPlay 地图绑定为 GLES2 纹理，叠加 QuickJS 零编译自定义主题与原厂 TTF 动态字形图集，实车跑满 **55–59 fps**，全程受三层自动保险丝保护；
   - **`v22.0` 独立通道（`capture=gles60`）**：无 CarPlay 地图流时由 `clusterd` 拉起纯 C GLES2 通道，通过 `eglGetProcAddress` 动态解析 GLES2 接口并用 `eglSwapInterval(dpy, 1)` 锁死 60fps 硬件 VSync，同时复用 `dash.c` 的 `g_dash_pxbuf[0..1]` 贴图合成文字。
3. **电脑端本地 CSV 回放与 1:1 浏览器试驾模拟器（`tools/preview/index.html`）**：无需上车，在电脑浏览器即可按 `1920×639` 精确还原左右 `295px` 信息框、大字导航卡、实车标定遮挡区参考线与 `v23` 自定义皮肤，支持拖入真实 `drive_logs/*.csv` 回放、一键导出 `dash.conf` 与截图，方便分享到 GitHub Discussions。
